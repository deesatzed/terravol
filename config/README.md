# Control artifact status

- `project.json`: canonical authority, implemented command boundary and separate capability status.
- `implementation_queue.json`: canonical VT ticket dependency/status source; Markdown queue is its readable view.
- `acceptance_matrix.json`: 120 planned application requirements, owner tickets and future test paths. No execution is implied.
- `offline.json`: validated default-deny scaffold profile and future application defaults; runtime NOT_IMPLEMENTED, no enabled models.
- `model_registry.json`: disabled, unverified candidates; committed foundation roster retained.
- `source_registry.json`: no approved sources and no subscription allowance; real feasibility not verified.
- `research.yaml`: retained v1 JSON-compatible fixture policy, not the active v2 profile. Exact v1 copies are archived.

These files do not themselves enforce live application permissions or implement a numerical engine. The supplied validator checks their cross-references and scaffold safety; runtime enforcement remains VT01–VT02 and later service work.
