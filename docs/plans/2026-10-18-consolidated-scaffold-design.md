# Consolidated VOLTERRA scaffold design

The user's request to create updated scaffolding and `GOAL_UPD.md` follows the v2 assessment and authorizes consolidating that design. The complete v2 event, cascade, arbitration and monitoring scope is retained. The recommended event-to-volatility chain is the first research proof; other contributions have independent comparisons.

## Delivery in this increment

Create one active goal, consistent project controls, an executable **scaffold validation/doctor** command, a Python 3.12 package boundary, safe offline configuration, machine-readable tickets and acceptance traceability, and implementation ownership documentation. Preserve v1 in a hash-verified archive and retain the candidate inputs unchanged. The scaffold command reports application work as unimplemented; it does not produce a fake forecast or pretend to expose future commands.

`GOAL_UPD.md` is authoritative. `GOAL.md` becomes a short pointer; `AGENTS.md` and the older root technical-document entry points refer to the active controls. The old T00–T03 assignment becomes a foundation checkpoint rather than a permanent scope cap. No private donor files are copied or executed.

## Decisions incorporated

- Integrity gates precede models. The first **scored offline** slice ends at VT05, with exact finite-state cascades and real baseline forecasts on synthetic data.
- VT02 owns early deterministic policy, transactional reservations, timeouts, idempotency and audit completion before VT06/VT10 can make external calls. VT16 owns learned/cost-aware selection later.
- Offline readiness and external-model integration have separate gates. TTM, Chronos-2 and TimesFM 2.5 remain the committed challenger roster; unavailable artifacts remain blocked rather than simulated.
- Monitoring has an observation/latency/error contract; event physical state, evidence state and instrument-specific propagation state remain separate.
- Conditional research watches connect event beliefs, downstream distributions, information arrival, model allocation, useful lead time and later scores.
- Selective model learning requires charged audit forecasts or supported propensities; unused experts have missing counterfactual forecasts.
- Origin-specific labels and cross-origin episode clustering have separate frozen identity rules.

## Interfaces and validation

Only `volterra doctor` and `volterra scaffold validate` are supplied by this scaffold. They read control artifacts, reject inconsistent IDs/dependencies/acceptance ownership or unsafe offline defaults, and return machine-readable status. They make no network calls and write no data. Forecast/replay/event/cascade commands remain future interfaces, explicitly unavailable.

Tests exercise cycles, missing acceptance ownership, unsafe external defaults, false completion claims and command exit/status behavior. These tests validate the scaffold, not application forecasting. Legacy fixture validation remains independently reproducible in the v1 archive.
