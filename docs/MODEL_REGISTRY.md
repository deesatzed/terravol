# Model integration status

Machine inventory: [model_registry.json](../config/model_registry.json). Active scope: [GOAL_UPD.md](../GOAL_UPD.md) §6. **All forecasting candidates are disabled and unimplemented.** No checkpoint, model benchmark or ML resource measurement is supplied by the scaffold.

Mandatory numerical controls are persistence, EWMA, Log-HAR and GJR-GARCH with compatible distributions/measurement links. Committed foundation candidates are TTM, Chronos-2 and TimesFM 2.5. TiRex-2, small Toto, Timestral-209M and other named alternatives remain optional or restricted challengers. Do not silently replace the committed roster.

`timestral_209m` is an optional VT06 covariate challenger, not an adapter or installed artifact. Its publisher documents multivariate targets, past and known-future covariates, CPU/GPU inference, and 21 marginal quantiles. It is relevant where a same-information covariate-aware distributional challenger is useful; those quantiles do not establish joint paths, cascade behavior, calibrated financial-volatility performance, or local resource feasibility. The code is Apache-2.0 while the 209M weights use a separate Modified MIT license with a stated revenue threshold, so intended use and exact artifact terms must pass an explicit license gate before download or enablement. [Model card](https://huggingface.co/mistralai/Timestral-209M), [weight license](https://huggingface.co/mistralai/Timestral-209M/blob/main/LICENSE), [source repository](https://github.com/mistralai/timestral/).

Before enabling any candidate, record actual code/checkpoint revision, artifact checksum, tested dependency lock, device/precision, resources, input/covariate semantics, output support/quantiles, joint-path capability, missingness and actual fallback identity. Audit code, weights and data terms independently for the intended deployment. Published capabilities are not local verification.

The scaffold's Python/build/jsonschema environment is separate from the eventual numerical worker environments. Do not treat its small dependency lock as compatibility proof for any foundation model. A blocked model test remains blocked even when the offline classical slice passes.
